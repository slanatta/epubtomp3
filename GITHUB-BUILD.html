Build it on GitHub

Microsoft's own Windows servers do the build. Nothing installs on your PC — not Python, not Inno Setup. You upload the folder, press a button, and download the finished installer about fifteen minutes later.

It's free. Public repositories get unlimited build time; the source is GPL v3 anyway, so making it public also settles the licence obligation in one go.

Steps

  1. Get a GitHub account

    Free, at github.com. Skip if you already have one.

  2. Make a new repository

    Click + at the top right → New repository. Call it epub2mp3. Choose Public. Leave every other box unticked — do not add a README, it just gets in the way. Click Create repository.

  3. Upload the files

    On the empty repository page, click uploading an existing file.

    Unzip EpubToMP3-source.zip on your PC, then open the EpubToMP3-source folder, select everything inside it, and drag that into the browser.

    This is the one step that can go wrong. Drag the contents, not the folder itself. When it's right, the file list in your repository starts with .github, build, src, tests. If you instead see a single EpubToMP3-source folder, delete the repository and try again — GitHub only notices the build recipe when it sits at the top level.

    Scroll down, click Commit changes.

  4. Run the build

    Click the Actions tab. Pick Build Windows installer on the left, then the Run workflow button on the right, and confirm.

    A yellow dot means it's running, and it takes about ten to fifteen minutes. Green tick means done. Red X means something failed — click into it, and send me whatever the red step says.

  5. Download the installer

    Click the finished run, scroll to the bottom, and under Artifacts you'll find:

    • EpubToMP3-Setup — the installer. This is the one you want.
    • EpubToMP3-portable — the same program as a plain folder, if you'd rather not install anything.

    They download as .zip files; unzip to get the Setup.exe inside.

What the build actually checks

It doesn't just compile blindly. Before it hands you anything, the workflow runs the test suite, then runs the finished executable against a generated test book to confirm it can still read an EPUB. If any of that fails, the build goes red rather than producing a broken installer.

Making a shareable link later

Build artifacts sit behind a GitHub login and expire after 90 days. If you want a plain download link to send people, create a tag: on the repository page go to Releases → Create a new release, type v1.0.0 as the tag, and publish. That triggers the same build and attaches the installer to a permanent public page.

If you change your mind

Everything still works the old way too. Install Python 3.12 on your PC and double-click build.bat — see BUILD-INSTRUCTIONS.html. The two routes produce the same installer.

Still expected on first launch: Windows SmartScreen will warn about the program, because it isn't code-signed. Click More info → Run anyway. Building on GitHub doesn't change that — only a paid certificate would.
